# Minesweeper Consistency SAT Benchmark

This repository accompanies an academic paper on the Minesweeper Consistency Problem (MCP), following Richard Kaye's proof that MCP is NP-complete in "Minesweeper is NP-complete", *The Mathematical Intelligencer* 22(2), 9-15 (2000). It provides a reproducible benchmark pipeline that generates MCP instances from actually played Minesweeper games, encodes them as SAT/Pseudo-Boolean formulas, and measures Glucose4 solve time. Paper link: [PAPER_LINK].

## Install

Use Python 3.11 on Linux or macOS for the closest match to the benchmark environment:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
```

Dependencies are pinned in `pyproject.toml`, including `python-sat[pblib,aiger]==1.9.dev15`, `matplotlib==3.10.6`, `psutil==7.0.0`, `pytest==8.4.2`, `pytest-cov==7.0.0`, and `mypy==1.17.1`.

## Reproduce

Regenerate the complete benchmark from scratch:

```bash
python -m mcp_bench.generate_instances --sizes 10,20,30,40,50,60 --games-per-size 30 --seed 42 --out instances/
python -m mcp_bench.run_benchmark --instances instances/ --out results/run_<date>/ --timeout 600
python -m mcp_bench.report --run results/run_<date>/
```

All numbers reported in the paper's Table [X] were generated by the exact commands above, run on Linux 6.19.13 x86_64 with a 12th Gen Intel(R) Core(TM) i5-1235U, 12 logical cores, 7.4 GiB RAM, and Python 3.14.4, on 2026-09-10, at git commit `cc1a5af969fc13bffc0a9b99139328dc4c56bb4e`, with results committed at [`results/run_2026-09-10/`](results/run_2026-09-10/). Anyone can reproduce this by running the same commands with the same seed; exact wall-clock times will vary by hardware, but relative scaling and SAT/UNSAT verdicts should match exactly.

No benchmark numbers are hand-written in this repository. `run_benchmark.py` records raw per-instance solver output, package versions, Python version, OS details, CPU/RAM metadata, git commit hash, timestamps, and the CLI arguments used for the run.

## Instance Sources

The primary instances are `played_game` states. A seeded engine generates a real Minesweeper board with the standard safe-first-click rule, then a deterministic no-guess bot repeatedly applies only the classic single-point rules. The benchmark snapshots the state where the bot gets stuck, or a configured fallback reveal fraction if the board is fully solved without guessing.

The secondary instances are `uniform_random` states. Mines are sampled uniformly from all cells and safe cells are revealed without game simulation. These are included as a comparison group so the paper can separate uniformly random structure from the correlated structure created by actual play.

The safe-first-click rule excludes the first clicked cell and its eight neighbors from mine placement, matching the convention used by mainstream Minesweeper implementations. The bot never guesses; it only marks mines or opens safe cells when a revealed clue locally forces that move. See [docs/METHODOLOGY.md](docs/METHODOLOGY.md) for the full generation, encoding, and measurement methodology.

## Tests

```bash
pytest -v --cov=mcp_bench
mypy src
```

The tests cover flood-fill behavior, safe-first-click invariants, no-guess bot deductions against ground truth, SAT/UNSAT encoding verdicts on small hand-checked instances, byte-identical serialization under fixed metadata, and an independent SAT sanity check for the AND-gate truth table notation used in the paper.
